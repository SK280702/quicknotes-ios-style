# QuickNotes — Android Reminders

Version: 1.1.0. Package: `com.quicknotes.app`. Minimum Android: 8.0 (API 26). Target: Android 15 (API 35).

## Product
An Android reminders app closely modeled on the familiar iOS Reminders layout: large headings, rounded smart-list cards, colored list icons, completion circles, grouped detail forms, and light/dark appearance. It uses original SVG icons and system fonts. It is not Apple software and is not a full 1:1 implementation of every iOS feature.

## Implemented behavior
- Today (including overdue), Scheduled, All, Flagged, and Completed views.
- Home Edit mode lets each Today/Scheduled/All/Flagged card be shown or hidden and reordered using its right-side hamburger handle. Layout preferences persist on this device. Lists can be dragged by their right-side handles in Edit mode; list order travels with sync. Reminder rows also support touch/mouse drag in Edit mode and keyboard arrow-key reorder. Task dragging stays within the same list and parent group; dragging switches sorting to manual order.
- Custom lists: name, seven icon choices, eight colors, rename, reorder, delete. Visible trash buttons in Edit mode delete lists and reminders. Native WebView confirmation dialogs now work; cancellation leaves data untouched. Deletion creates sync tombstones and cancels associated alarms.
- New reminders use a blue circular + button. The editor groups Title, Notes, and URL together. Date and Time are separate switches with conditional date/time inputs. Turning Time on also turns Date on; turning Date off turns Time/Repeat/Urgent off. Repeat appears only with a date and shows an interval selector only when its switch is enabled. Date-only reminders use 09:00 local time and show no time in the row. Advanced Details retains tags, flags, priority, subtasks, and attachments. Existing date/time reminders migrate when opened without dropping their saved date.
- Every reminder has one stable unique ID. Completing a reminder marks the existing record done and hides it; the Show Completed switch in each list displays all completed and active reminders together. No duplicate record is created, even for repeats. Completing a repeating reminder stores `nextDue` on that same ID. It remains checked until the next due time, when the same record reactivates. Parent completion and reactivation propagate to subtasks. Uncompleting clears the pending next occurrence. Daily/weekly/monthly/yearly repeats remain supported. Existing distinct records made by older versions are retained; the app does not delete similarly named reminders automatically.
- Search title, notes, and tags. Tag buttons filter reminders. Sort by manual order, title, due date, or priority. Move reminder up/down in its editor. Show/hide completed and clear completed.
- Multiple photos/files per item via Android's multi-select document picker. Files are copied into private app storage, survive original-file deletion, and open in a compatible Android viewer. Images preview as small square thumbnails in the reminder row and in Details; row previews replace attachment names. Non-image files use a square file icon with an accessible filename. Native previews are downsampled to at most 512 pixels and cached; the original attachment remains intact. Removing an attachment removes its reference; unused private files are retained in 1.1.0.
- Persistent offline data saved with temporary-file rename; all file operations and bundle synchronization run on a serial background executor.
- Normal due-date notifications use AlarmManager inexact alerts. Urgent mode enables Date and Time and uses `setAlarmClock` exact scheduling, with a foreground service playing the system alarm sound in a loop and vibrating. Notification actions and the lock-screen alarm screen offer Dismiss and Snooze 5 minutes. Dismiss stops ringing without completing the reminder or creating another ID. Snooze preserves the original reminder ID and due date; completing/deleting/changing an urgent reminder cancels its pending or active alarm. Multiple simultaneous alarms remain individually tracked. Ringing stops after five minutes if unattended.
- Android 12+ requires user-granted Alarms & reminders access; Android 13+ also needs notification permission for visible alerts. Urgent setup offers the appropriate system settings and requests notification permission. Without exact-alarm access, an urgent reminder is visibly pending permission and is not silently scheduled as an inaccurate urgent alarm. Android 14+ may also require full-screen intent access for automatic lock-screen display; without it, sound still rings and the notification opens the alarm controls. Alarm volume, DND configuration, force-stop, device shutdown, and vendor battery policies remain OS-controlled. Scheduling restores on launch/reboot and exact-permission/clock change broadcasts. No claim of ringing while the phone is off or force-stopped.

## Google Drive synchronization
No OAuth client ID, developer account, API key, or server is needed. Uses Android's Storage Access Framework with Google Drive's installed document provider. Select **Sync & Backup → Create Sync File**, choose **Drive** in the picker, and save `QuickNotes-sync.zip`. On another device, choose **Connect Existing Sync File** and select the same file. The provider must grant persistent read/write permission. Some providers/accounts may not support updating files; the app reports errors and retains local data.

Each bundle contains `data.json` and all referenced attachment bytes. Sync reads the selected bundle, merges by record ID and per-record modification timestamp, persists locally, then writes the merged bundle. Deleted records remain as tombstones to prevent resurrection. Equal-time conflicts use a deterministic serialized-record tie break. Clock accuracy affects conflict resolution. Simultaneous writes by two devices are not transactionally locked and may race; for dependable transfer, finish syncing one device before syncing the other.

Sync runs after saved edits (1.8-second debounce), after returning to the app, and on **Sync Now**. The Drive provider controls actual cloud upload timing and may serve cached data. This is file-based Drive sync, not Google Tasks sync, iCloud sync, continuous background network sync, or collaborative real-time editing. Google Drive must be installed and signed in. Connecting a file performs a merge, not a destructive replacement. Disconnect keeps local data.

Limits: 20 MiB per attachment; 100 MiB total uncompressed bundle; 5 MiB manifest when importing. Import rejects unsafe file paths, unsupported versions, and missing attachments. Bundle export/import includes attachments. An internal `last-sync.zip` is kept before the remote file is rewritten. Provider writes cannot be guaranteed atomic; local reminders are retained if a cloud write fails.

## Architecture and privacy
Local HTML/CSS/JavaScript rendered in Android WebView, Java native bridge, private JSON store, read-only non-exported attachment ContentProvider, AlarmManager receiver. WebView serves only packaged assets and private attachment bytes from `https://quicknotes.local`; external navigation opens the browser. No internet permission, advertising, tracking, third-party backend, broad storage permission, or Apple assets. Drive receives data only via the user-selected provider. Portable bundles are plain ZIP files and are not encrypted. Android OS app backup is disabled to avoid splitting reminder data from its private attachments.

## Scope gaps relative to iOS Reminders
No Siri/Apple Intelligence, iCloud, location/message-triggered alerts, widgets, grocery categorization, shared-list assignment, sections, or Apple-native gesture parity. The app provides the main reminders workflow and attachment-capable Drive file sync; it must not be described as exhaustive iOS parity.

## Build and release
`./install.sh` installs the Android 35 SDK/build tools (requires JDK 17, curl, unzip). `./build.sh` compiles Java/resources, packages assets, aligns and signs the APK, and verifies signatures. No Gradle or paid service is required. `./run.sh` builds, installs with adb, and launches when adb is available. `./cli.sh test` runs Node model tests; `./cli.sh build` builds.

For stable release signing, restore the privately retained QuickNotes key and set `QN_KEYSTORE` and `QN_KEYSTORE_PASSWORD`. Never commit keys. The initial key's password is `android` (key custody is private). Developer builds create their own key under ignored `build/`; a differently signed APK cannot update the published app.

Release assets: `QuickNotes-v1.1.0.apk`, `QuickNotes-source-v1.1.0.zip`, `spec.md`, and `SHA256SUMS`. A main-branch workflow builds and tests then publishes the same main commit as tag `v1.1.0`; the workflow uploads the already signed release APK committed under `release/` and verifies it against a fresh source build. Future releases must be signed using the retained key.

## Validation
Model tests cover stable-ID completion without duplicate rows, completed visibility, recurrence rollover, drag ordering, merge/tombstones, date boundaries, duplicate-ID rejection, and unique new IDs. Playwright tests cover smart-card visibility/persistence, pointer drag for cards/lists/tasks, date/time/repeat/urgent switches, attachment thumbnails, completed toggles, direct/editor deletion, and dark appearance. The native Android 15 instrumentation suite checks actual WebView deletion confirmation, background exact-alarm delivery and looping audio, Dismiss/Snooze, cancellation after completion/deletion, and same-ID native recurrence. Release publishing requires all model/UI/native tests and matching source/APK verification to pass. Google Drive round trips and manufacturer-specific alarm behavior still require real-device verification.
