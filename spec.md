# QuickNotes — Android Reminders

Version: 1.2.0. Package: `com.quicknotes.app`. Minimum Android: 8.0 (API 26). Target: Android 15 (API 35).

## Product
An Android reminders app closely modeled on the familiar iOS Reminders layout: large headings, rounded smart-list cards, colored list icons, completion circles, grouped detail forms, and light/dark appearance. It uses original SVG icons and system fonts. It is not Apple software and is not a full 1:1 implementation of every iOS feature.

## Implemented behavior
- Today (including overdue), Scheduled, All, Flagged, and Completed views.
- Home Edit mode lets each Today/Scheduled/All/Flagged card be shown or hidden and reordered using its right-side hamburger handle. Layout preferences persist on this device. Lists can be dragged by their right-side handles in Edit mode; list order travels with sync. Reminder rows also support touch/mouse drag in Edit mode and keyboard arrow-key reorder. Task dragging can reorder or create subtasks across parent groups; dragging switches sorting to manual order.
- Custom lists: name, seven icon choices, eight colors, rename, reorder, delete. Visible trash buttons in Edit mode delete lists and reminders. Native WebView confirmation dialogs work; cancellation leaves data untouched. Deletion creates sync tombstones and cancels associated alarms.
- New reminders use a blue circular + button. The editor groups Title, Notes, and URL together. Date and Time are separate switches with conditional date/time inputs. Turning Time on also turns Date on; turning Date off turns Time/Repeat/Urgent off. Repeat appears only with a date and shows an interval selector only when its switch is enabled. Date-only reminders use 09:00 local time and show no time in the row. Advanced Details retains tags, flags, priority, subtasks, and attachments. Existing date/time reminders migrate when opened without dropping their saved date.
- Every reminder has one unique ID. Completing a normal reminder marks it done and hides it; Show Completed reveals all completed items. Completing a repeating reminder keeps that completed record and immediately creates the next uncompleted occurrence, including its photo references and nested subtasks. Each occurrence has a different ID. Series IDs and deterministic next-occurrence IDs prevent two devices completing the same occurrence from producing separate future copies. Unchecking/rechecking an occurrence does not clone the same next due occurrence twice. Older 1.1.0 `nextDue` records migrate to this new rule on opening. Already distinct records are retained.
- Tap a reminder title/notes to edit inline. Quick bar: Date, Location, Tags, Flag, Photos. With a date, Time/Urgent/Repeat buttons are added and configured dates/times appear blue. Date menu: None, Today, Tomorrow, Next Weekend (next Saturday), Next Week (seven days), Custom. Time menu: None, 9 AM, noon, 3 PM, 6 PM, 9 PM, Custom. Custom opens only scheduling fields: Date, Time, Urgent, Repeat, Early Reminders. Custom time opens the time picker. Early reminders support 5/15/30 minutes, 1/2 hours, 1/2/7 days before, as separate normal notifications; urgent audio still rings at the main due time.
- Swipe left reveals Details, Flag, Delete in that order. Details opens the full reminder editor; Flag toggles immediately. Full swipe (over 72% of the row width) or a second left swipe on an open row deletes it and all descendants, creating tombstones. Partial swipe right closes the action buttons. Swipe deletion is immediate.
- Drag handles for lists/tasks always work, without Edit. Hold a reminder row for 420 ms to lift it, or drag its handle. A floating copy follows the pointer, the source fades, and an invalid drop animates back. Drop near a reminder's upper/lower edge to reorder alongside it; drop into its center to make a subtask, including across parent groups. Cycles are rejected. Children follow list moves. Add Subtask in the inline reminder creates a child immediately. The full editor also exposes Add Subtask. Smart card visibility/reorder remains in Edit. The top-right … menu offers Edit and Sync Settings, plus List Options within a list.
- Built-in repeat choices: Daily, Weekdays, Weekends, Weekly, Monthly, Yearly. Custom supports Hourly/Daily/Weekly/Monthly/Yearly and an interval from 1–999. Weekly Each selects weekdays; monthly/yearly Each selects calendar dates 1–31. On The… selects First–Fifth or Last and a weekday for monthly/yearly rules. A missing fifth weekday/date is skipped; ordinary monthly/yearly repeats clamp month ends. Recurrence uses local calendar time, preserves due time, and skips past occurrences.
- Search title, notes, and tags. Tag buttons filter reminders. Sort by manual order, title, due date, or priority. Move reminder up/down in its editor. Show/hide completed and clear completed.
- Multiple images per item via Android's multi-select document picker. Files are copied into private app storage, survive original-file deletion, and preview inside the app. Images preview as small square thumbnails in the reminder row and in Details; row previews replace attachment names. New document selection is restricted to image MIME types and the native bridge rejects other file types. Existing legacy file references remain in backups; reminder rows show only images. Tap an image to open a full-screen in-app preview; close, tap the backdrop, or Back dismisses it. Native previews are downsampled to at most 512 pixels and cached; the original attachment remains intact. Removing an attachment removes its reference; unused private files are retained in 1.2.0.
- Persistent offline data saved with temporary-file rename; all file operations and bundle synchronization run on a serial background executor.
- Normal due-date notifications use AlarmManager inexact alerts. Urgent mode enables Date and Time and uses `setAlarmClock` exact scheduling, with a foreground service playing the system alarm sound in a loop (an original bundled tone is used if the system sound is missing or unreadable) and vibrating. A normal title/notes notification accompanies the urgent foreground alarm. Both normal notifications and the alarm notification/control screen offer Dismiss and Mark As Completed. Dismiss stops ringing without completing the reminder or creating another ID. Mark As Completed updates the existing reminder and creates the next occurrence when repeating; completing/deleting/changing an urgent reminder cancels its pending or active alarm. Multiple simultaneous alarms remain individually tracked. Ringing stops after five minutes if unattended.
- Android 12+ requires user-granted Alarms & reminders access; Android 13+ also needs notification permission for visible alerts. Urgent setup offers the appropriate system settings and requests notification permission. Without exact-alarm access, an urgent reminder is visibly pending permission and is not silently scheduled as an inaccurate urgent alarm. Android 14+ may also require full-screen intent access for automatic lock-screen display; without it, sound still rings and the notification opens the alarm controls. Alarm volume, DND configuration, force-stop, device shutdown, and vendor battery policies remain OS-controlled. Scheduling restores on launch/reboot and exact-permission/clock change broadcasts. No claim of ringing while the phone is off or force-stopped.

## Location reminders and Google Maps
Location stores latitude/longitude, address, arrival/departure mode, and radius 100.584–241401.6 metres (330 ft–150 miles). The location editor offers Android address search, current position, and a dedicated Google Maps picker. The picker draws a blue circle with a distance slider, lets the user tap the map or drag the circle's center, and returns the selected coordinates. Configure a Maps JavaScript API key in Sync Settings → Google Maps API Key; enable that API in Google Cloud, apply appropriate referrer restrictions for `https://quicknotes.local/*`, and follow Google's quotas/billing requirements. No key is bundled, synced, or committed. Map loading needs internet and a valid key. Address search depends on Android's installed geocoder/network service. Current-position selection requires an enabled location provider.

Location monitoring is opt-in with Android location permission and an ongoing monitoring notification. A platform LocationManager foreground service requests GPS/network updates every 30 seconds/25 metres when available. Precise location is recommended for the minimum radius. Background permission (Allow all the time) enables restoration where Android allows it; foreground monitoring started while the app is visible can continue under its ongoing notification. Permission and location settings remain user-controlled. Entering the area triggers arrival; leaving requires a previous inside reading. Persistent transition state prevents repeat alerts while still inside, and the boundary has up to 30 m hysteresis. Inaccurate fixes wider than the selected radius are skipped. Completed/deleted/list-deleted reminders are ignored and monitoring stops when none remain. Updates can be delayed by GPS reception, Android restrictions, force-stop, power-saving, or device shutdown. This is not guaranteed immediate geofencing while the phone is off.

## Google Drive synchronization
Drive file sync needs no OAuth client ID, developer account, API key, or server. Uses Android's Storage Access Framework with Google Drive's installed document provider. Select **Sync & Backup → Create Sync File**, choose **Drive** in the picker, and save `QuickNotes-sync.zip`. On another device, choose **Connect Existing Sync File** and select the same file. The provider must grant persistent read/write permission. Some providers/accounts may not support updating files; the app reports errors and retains local data.

Each bundle contains `data.json` and all referenced attachment bytes. Sync reads the selected bundle, merges by record ID and per-record modification timestamp, persists locally, then writes the merged bundle. Deleted records remain as tombstones to prevent resurrection. Equal-time conflicts use a deterministic serialized-record tie break. Clock accuracy affects conflict resolution. Simultaneous writes by two devices are not transactionally locked and may race; for dependable transfer, finish syncing one device before syncing the other.

Sync runs after saved edits (1.8-second debounce), after returning to the app, and on **Sync Now**. The Drive provider controls actual cloud upload timing and may serve cached data. This is file-based Drive sync, not Google Tasks sync, iCloud sync, continuous background network sync, or collaborative real-time editing. Google Drive must be installed and signed in. Connecting a file performs a merge, not a destructive replacement. Disconnect keeps local data.

Limits: 20 MiB per attachment; 100 MiB total uncompressed bundle; 5 MiB manifest when importing. Import rejects unsafe file paths, unsupported versions, and missing attachments. Bundle export/import includes attachments. An internal `last-sync.zip` is kept before the remote file is rewritten. Provider writes cannot be guaranteed atomic; local reminders are retained if a cloud write fails.

## Architecture and privacy
Local HTML/CSS/JavaScript rendered in Android WebView, Java native bridge, private JSON store, read-only non-exported attachment ContentProvider, AlarmManager receiver. WebView serves only packaged assets and private attachment bytes from `https://quicknotes.local`; external navigation opens the browser. Internet access is used for Google Maps/address lookup. No advertising, tracking backend, broad storage permission, or Apple assets. The separate Maps WebView has no Native bridge; the private reminder WebView serves only local assets. Google receives the selected map coordinates and address when its picker is opened; local location monitoring does not send GPS positions to a QuickNotes server. Drive receives data only via the user-selected provider. Portable bundles are plain ZIP files and are not encrypted. Android OS app backup is disabled to avoid splitting reminder data from its private attachments.

## Scope gaps relative to iOS Reminders
No Siri/Apple Intelligence, iCloud, message-triggered alerts, widgets, grocery categorization, shared-list assignment, sections, or Apple-native gesture parity. The app provides the main reminders workflow and attachment-capable Drive file sync; it must not be described as exhaustive iOS parity.

## Build and release
`./install.sh` installs the Android 35 SDK/build tools (requires JDK 17, curl, unzip). `./build.sh` compiles Java/resources, packages assets, aligns and signs the APK, and verifies signatures. No Gradle or paid service is required. `./run.sh` builds, installs with adb, and launches when adb is available. `./cli.sh test` runs Node model tests; `./cli.sh build` builds.

For stable release signing, restore the privately retained QuickNotes key and set `QN_KEYSTORE` and `QN_KEYSTORE_PASSWORD`. Never commit keys. The initial key's password is `android` (key custody is private). Developer builds create their own key under ignored `build/`; a differently signed APK cannot update the published app.

Release assets: `QuickNotes-v1.2.0.apk`, `QuickNotes-source-v1.2.0.zip`, `spec.md`, and `SHA256SUMS`. A main-branch workflow builds and tests then publishes the same main commit as tag `v1.2.0`; the workflow uploads the already signed release APK committed under `release/` and verifies it against a fresh source build. Future releases must be signed using the retained key.

## Validation
Model tests cover series completion/unique next IDs, subtree/list movement and cycle rejection, custom calendar recurrence, migration, month ends, merge/tombstones, drag order, completed visibility, and unique new IDs. Playwright tests exercise inline editing, partial/full/second swipe, action buttons, quick date/time/urgent/repeat controls, past-time reset, custom ordinal selection, early-reminder selection, image-only filtering/previews, subtask creation/drag, floating motion, menus, persistence and dark layout. Android 15 native tests verify real WebView dialogs, background exact alarms/looping sound, notification title/notes/actions, completion/cancellation/recurrence, and location arrival/departure transitions with controlled coordinates. Source/APK matching checks verify the published privately signed APK against a clean build.

Live Google Maps key loading, real-world GPS arrival/departure, Google Drive round trips, and manufacturer-specific power restrictions require real-device verification; no Google Maps key is available in the build environment. Native location tests verify transition/delivery logic, not a live journey.
